### Upstream generation / lineage (Phase 0 requirement)

- The Django repo's own settings declare the target baseline:
  `PIPRAPAY_VERSION = {"version_name": "v3.0.0-beta", "version_code": "3.0.0", "channel": "beta"}`
  (`config/settings.py:20-21`). The only upstream tag is **`v3.0.0`**, which is the
  same product generation as the reference the port was written against.
- Source lineage is **direct**: the port's docstrings cite exact upstream
  `file:line` ranges from this tree (`pp-functions.php`, `pp-adapter.php`,
  `index.php`, per-gateway `class.php`). The historical baseline and the current
  official `main` are therefore the **same generation** — a single comparison is
  valid, and no "A/B two-generation" split is required.
- Caveat: upstream `main` (`021ecd3`) is a few commits ahead of `v3.0.0`
  (sponsor/README/SEO edits). No functional divergence relevant to the port was
  found in those commits.

## 2. Dependency manifests

`requirements.txt` (working tree): `Django>=5.0,<5.3`, `requests>=2.31,<3`,
`Pillow>=10,<13`, `cryptography>=41,<51`, `bcrypt>=4,<6`.

`requirements-lock.txt` (untracked, new): exact pins for
Python 3.14.7 + Django 5.2.18 (asgiref 3.12.1, bcrypt 5.0.0, cffi 2.1.1,
cryptography 50.0.2, Django 5.2.18, numpy 2.5.3, pillow 12.3.0, pycparser 3.0,
requests 2.34.2, sqlparse 0.6.0).

Note: `bcrypt` is imported only by `check_requirements.py` (to report it as
"available"); passwords are actually hashed with Django's default PBKDF2
(`make_password`), not bcrypt. The PHP original used `password_hash()` (bcrypt
by default), so hashes are **not wire-compatible** across the two stacks. See
finding `DEP-1`.

## 4. Databases, gateways, tests, CI

- **Models:** 23 Django models (`core/models.py`), all `db_table` = `pp_*`
  (legacy names kept). 2 migrations (`core/migrations/0001`, `0002`).
  `db.sqlite3` exists locally but is correctly git-ignored (`.gitignore`).
  Only `core.0001_initial` and `core.0002_addon_...idx` exist; the second is
  untracked.
- **Gateways:** 48 registered slugs (`gateways/plugins.py:SPECS`) —
  13 `api`, 30 `automation`, 5 `manual`. 13 bespoke HTTP ports in
  `gateways/api_gateways.py`.
- **Tests:** 7 modules under `tests/` (`test_parity.py`, `test_parity2.py`,
  `test_parity3.py`, `test_gateways.py`, `test_coverage.py`,
  `test_security.py`, `test_workflows.py`). 196 tests collected, all passing
  after this audit's fixes (108 at baseline HEAD).
- **CI:** `.github/workflows/ci.yml` (new) — Python 3.12/3.13/3.14
  matrix: compileall, `check`, `makemigrations --check`, `check_requirements`,
  `test tests`. No linter/formatter/type-checker or dependency-audit step.
  **Push note:** present in the working tree but not in commit `46f07ca` —
  the GitHub OAuth token used for the push lacks the `workflow` scope
  GitHub requires to create workflow files. Add after
  `gh auth refresh -h github.com -s workflow` (or via the web UI), then
  push.
